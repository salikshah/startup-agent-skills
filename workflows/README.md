# Workflows

Importable automations that put the skills in this repo to work: a Chatwoot AI support agent with human handoff, ElevenLabs voice flows, and startup-ops workflows (content, growth, customer, ops). Each one is an n8n export or an Activepieces build guide, documented next to the file and checked by `workflows/tools/validate_workflows.py`.

**27 n8n workflows** (17 original, 10 adapted from CC BY 4.0 sources) and **11 Activepieces build guides**, across six categories: chatwoot (4 n8n), voice (7 n8n), content (3 n8n), growth (4 n8n), customer (5 n8n), ops (4 n8n).

- `n8n/<category>/<slug>.json` is an n8n workflow export, with `<slug>.md` next to it covering purpose, setup, credentials and a test.
- `activepieces/<category>/<slug>.md` is an Activepieces build guide (pieces and steps) plus links to related official templates.
- `recipes/` holds end-to-end guides: [Chatwoot + n8n AI support](recipes/chatwoot-n8n-ai-support.md) and [ElevenLabs voice](recipes/elevenlabs-voice.md).
- [CREDITS.md](CREDITS.md) lists every source, author and license.

## Import

**n8n:** *Workflows > Add workflow > ... menu > Import from File* (or paste the JSON onto the canvas). Then open each node that shows a warning and pick your credential. Every credential ID in these files is the placeholder `REPLACE_WITH_YOUR_CREDENTIAL_ID`, so nothing connects until you choose your own. Most workflows start with a **Config** node: edit it first.

**Activepieces:** build the flow from the guide, or open a linked gallery template (*Use template*) and change it to match. To move a flow between instances, use *Export flow* / *Import flow* from the flow menu.

## Credentials you will need

| Service | n8n credential type | Used by |
|---|---|---|
| Chatwoot | Header Auth, name `api_access_token` (agent-bot token or user access token) | chatwoot/* |
| ElevenLabs | Header Auth, name `xi-api-key` | voice/* |
| OpenAI or OpenAI-compatible (OpenRouter, Groq, Ollama `http://ollama:11434/v1`) | OpenAI API (set Base URL for non-OpenAI) | most AI steps |
| Google Sheets / Gmail / Drive | Google OAuth2 | logging, drafts, approvals |
| Slack, Telegram | Slack API, Telegram API | alerts, digests |
| Qdrant, Postgres | Qdrant API, Postgres | RAG workflows (both ship in the n8n self-hosted AI starter kit) |

Keep keys in the n8n/Activepieces credential store. Never paste them into Code nodes, Config nodes or workflow JSON.

## Self-hosting quickstart

1. **n8n + Postgres + Qdrant + Ollama:** clone [n8n-io/self-hosted-ai-starter-kit](https://github.com/n8n-io/self-hosted-ai-starter-kit) (Apache-2.0), copy `.env.example` to `.env`, set the passwords and `N8N_ENCRYPTION_KEY`, then `docker compose --profile cpu up` (use `gpu-nvidia` if you have one). n8n runs on http://localhost:5678, Qdrant on :6333. Inside the compose network the hosts are `postgres`, `qdrant` and `ollama`.
2. **Chatwoot:** follow the [Chatwoot Docker guide](https://developers.chatwoot.com/self-hosted/deployment/docker), or use the combined compose file in [recipes/chatwoot-n8n-ai-support.md](recipes/chatwoot-n8n-ai-support.md), which runs Chatwoot, n8n, Postgres (pgvector) and Redis together.
3. **Activepieces:** for one machine, `docker run -d --name activepieces -p 8080:80 -v ~/.activepieces:/root/.activepieces -e AP_DB_TYPE=PGLITE -e AP_REDIS_TYPE=MEMORY -e AP_FRONTEND_URL="http://localhost:8080" activepieces/activepieces:latest` ([hobbyist install](https://www.activepieces.com/docs/install/options/docker)); for production use the [Docker Compose setup](https://www.activepieces.com/docs/install/options/docker-compose) with Postgres and Redis.
4. Webhooks from Chatwoot Cloud, ElevenLabs or Telegram need a public HTTPS URL. Set `WEBHOOK_URL` on n8n and put it behind a reverse proxy or a tunnel.

## Safety rules these workflows follow

- **Drafts, not sends.** Outreach, follow-ups and customer replies are created as Gmail drafts. No workflow here sends cold email.
- **Human approval before anything irreversible.** The post-eval gate asks for an *Approve* click before queueing a post, and its X publish node ships disabled. Chatwoot handoff sets the conversation to `open` and never resolves or closes it.
- **Hard limits in code.** Scores, lengths and arithmetic are checked in Code nodes; the model only proposes.
- **Allow-lists and secrets.** The Telegram bots answer only your chat id. ElevenLabs tool calls need an `x-tool-secret` header, and post-call webhooks are HMAC-verified.
- **Cost caps.** Limit nodes bound LLM calls per run. Put usage limits on your API keys as well.

## Validate

```bash
python workflows/tools/validate_workflows.py
```

The validator checks that every n8n JSON parses with `nodes` + `connections`, node types and versions are well formed, every connection and every `$('Node')` expression points at a real node, no node is left unwired, credential IDs are placeholders, nothing looks like a key or token, and each JSON has a matching `.md` with a *Source and license* section. It exits non-zero on failure and runs in CI.
